# StarPilot S0 · 真机验证协议

> 目的：在进入 S1 之前，用一份可重复的测试把「能不能装、传感器准不准、计时可不可靠、通信通不通」变成可验收的事实。
>
> 适用：HUAWEI Watch 5 46mm + Android 手机。
>
> 规则：**没有记录 = 没通过**。每项都要填结果、时间、环境、异常现象。

---

## 0. 测试前准备

### 0.1 硬件与环境

- [ ] Watch 5 充满电（≥80%），关闭省电模式。
- [ ] 手表与 PC 在同一 WLAN；记录 SSID 与手表 IP。
- [ ] Android 手机安装最新版华为运动健康，手表已配对并连接。
- [ ] 准备：手机水平仪 App、手机指南针 App、卷尺/量角器（可选）、红光头灯。
- [ ] 选一个开阔地（公园/楼顶无遮挡）做基线；阳台做真实环境对比。
- [ ] 夜间测试注意安全：不要站在栏杆上，不要在阳台边缘探身。

### 0.2 软件

- [ ] 华为开发者账号（已实名认证）。
- [ ] DevEco Studio 26.0.0.865（自带 HarmonyOS 26.0.0 SDK，无需单独装 API 23 SDK）。
- [ ] 确认工程 `modelVersion` 为 26.0.0，`compileSdkVersion` 使用 IDE 默认 26.0.0。
- [ ] `hdc` 可用（DevEco 自带，或 Command Line Tools 的 `sdk/default/openharmony/toolchains`）。
- [ ] 本仓库 `starpilot-watch/`。

### 0.3 手表开发者模式

1. 设置 → 关于 → 连续点击版本号 7 次。
2. 设置 → 系统 → 开发人员选项。
3. 打开 **HDC 调试**、**无线调试**。
4. 记录屏幕显示的 **IP:端口**。

> 若找不到“开发人员选项”，先确认版本号点击是否生效；部分固件在“设置 → 关于手表”。

### 0.4 模拟器预检（可选，不能替代真机）

DevEco 26 支持 Wearable 模拟器。建议先用它排除编译/布局问题，再上真机。

1. `Tools → Device Manager → Local Emulator → New Emulator`。
2. 设备类型选 **Wearable**；优先选 466×466 圆屏镜像（没有就选最接近的）。
3. 镜像 API 23/24/26 都可以：工程 `compatibleSdkVersion = 6.1.0(23)`，高版本镜像可安装。
4. 启动模拟器 → Run `entry`。

**能验证**

- 能否编译、签名、安装、启动。
- 四页在圆屏上的裁切、字号、翻页、页码点。
- 偏好存储、HTTP、前台计时。
- ArkTS/ArkUI 运行时崩溃与日志。

**不能验证（必须真机）**

- 加速度/陀螺仪/磁力计/旋转矢量是否存在、频率、噪声。
- 方位精度、磁干扰、倾角、抖动。
- 表冠硬件事件、振动强度/延迟。
- 息屏/后台计时、功耗、Wear Engine。

**判定规则**：模拟器结果只能记为 `EMU PASS`，不能关闭 G1–G4。传感器页在模拟器上报错或无数据是预期现象，不要据此改代码。

## 1. 构建、签名、安装

### 1.1 打开工程

DevEco Studio → Open → 选择 `starpilot-watch`。

首次 Sync 若报 `modelVersion` / `hvigor` 不匹配：

1. 用本机 DevEco 新建一个空 **Wearable** 工程（Application → Empty Ability → Device type: Wearable → ArkTS）。
2. 把本仓库的 `AppScope/`、`entry/src/main/` 覆盖到新工程。
3. 保留新工程的 `build-profile.json5`、`oh-package.json5`、`hvigor/`、`entry/build-profile.json5`、`entry/oh-package.json5`。
4. 新工程会自动生成 `modelVersion 26.0.0`；把 `compatibleSdkVersion` 与 `targetSdkVersion` 设为 `6.1.0(23)`，`compileSdkVersion` 保持 26.0.0（或省略）。

### 1.2 签名

1. File → Project Structure → Signing Configs。
2. 勾选 **Automatically generate signature**，登录华为账号。
3. 连接手表后点 **Sign In / Generate**；IDE 会把当前设备 UDID 写入调试 Profile。
4. 若自动签名失败：
   - AGC → 证书、APP ID、Profile → 添加调试设备（填 T01 的 UDID）→ 下载 `.p7b`；
   - 在 Signing Configs 中手动指定 `.p12`、`.cer`、`.p7b`。

### 1.3 安装与启动

```bash
# DevEco: Run 'entry'（Shift+F10）
# 或命令行：
hvigorw assembleHap --mode module -p product=default -p buildMode=debug --no-daemon
hdc install -r entry/build/default/outputs/default/entry-default-signed.hap
hdc shell aa start -a EntryAbility -b com.starpilot.audit
```

### 1.4 抓日志

```bash
# 另开一个终端，测试全程保持
hdc hilog | grep StarPilotAudit > s0_audit.log
```

应用内每个页面都有“输出…日志”按钮；日志 tag 固定为 `StarPilotAudit`。

### T06 方位精度（核心）

#### 参考基准（按可靠性排序）

1. **已知地标方位**：在地图上选 3 个远处地标（南、西南、西），用坐标算出真方位。
2. **太阳方位**：用 Stellarium/AstroPy 算当时当地太阳方位，用影子方向辅助；不要直视太阳。
3. **手机指南针**：最方便，但本身有 ±5° 误差，只作交叉参考。

#### 步骤（开阔地基线）

1. 站在开阔地，远离金属、车辆、音箱、手机。
2. 手表做 8 字校准 3 次。
3. 用 12 点方向依次对准 N/E/S/W/NE/SE/SW/NW（可用手机指南针找方向）。
4. 每个朝向稳定 5 s，记录罗盘页 `AZ` 与参考方位。
5. 顺时针做一遍，逆时针再做一遍，检查回差。

#### 步骤（阳台真实环境）

1. 回到阳台，重复南/西南/西三个朝向。
2. 记录磁场 µT 与“磁场正常/干扰”状态。
3. 分别记录“靠近栏杆”和“退后 1 m”的读数。

#### 通过标准

| 指标 | 开阔地 | 阳台 |
|---|---|---|
| RMS 误差 | ≤7° | ≤10° |
| 最大误差 | ≤12° | ≤15° |
| 静止抖动（60 s 标准差） | ≤2° | ≤3° |
| 顺/逆时针回差 | ≤5° | ≤8° |

> 注意：如果手表输出的是磁北，而参考是真北，误差里会包含当地磁偏角。先记录磁偏角（NOAA/WMM 查询），再判断是“系统偏差”还是“随机误差”。系统偏差可用归零/磁偏角修正，随机误差不能。

**结果**：______

**判定分支**

- 准时振动 → S1 计时器可按前台方案实现。
- 不振动但重开后补发 → S1 需持久化 `endTime`，重开时补提醒。
- 完全不执行 → S1 必须加“屏幕常亮”或改系统闹钟/通知方案。

### T20 Wear Engine（G4，阻塞项）

> 这一项在 S0 当天通常**无法完成**，因为权限审批需要 1–2 周。先做“材料准备”，不要阻塞 S1。

#### 准备

- [ ] AGC 创建应用，包名与 Android 工程一致（例如 `com.starpilot.phone`）。
- [ ] 记录 Android 签名证书 SHA256。
- [ ] AGC → 开放能力管理 → Wear Engine → 申请“设备基础信息”“消息通知”。
- [ ] 上传权限说明、使用场景、用户授权路径。

## 4. S0 退出判定

四条门禁全部满足才可进入 S1：
